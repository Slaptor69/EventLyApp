# ADR 0002: Политика кэша новостей

## Статус

Принято.

## Контекст

Лента новостей должна загружать удаленные статьи NYT, периодически обновляться и хотя бы один раз использовать кэшированные данные. UI не должен блокироваться, пока идет сетевой запрос, а у кэша должна быть понятная стратегия очистки.

## Решение

Приложение хранит последний успешный снимок новостей в Room в течение 24 часов. При старте экрана ViewModel сначала читает кэшированный snapshot и сразу отображает его, если он есть. После этого запускается сетевое обновление, которое заменяет кэшированные метаданные.

Изображения кэшируются отдельно в cache directory приложения. Имена файлов создаются на основе hash от URL изображения. Повторно используемые изображения остаются, пока они свежие; неиспользуемые файлы удаляются после успешного обновления метаданных. Если metadata cache истек, очищаются и метаданные, и кэшированные изображения.

Для Room-кэша metadata допустима destructive migration: это не пользовательские данные, а восстановимый кэш, который можно заново получить из NYT API.

Экран настроек также дает ручное действие очистки кэша. Пользователь должен подтвердить его в диалоге, прежде чем `SettingsCommand.ClearNewsCache` очистит Room metadata и кэшированные файлы изображений.

## Итоги

Лента открывается быстро, если есть предыдущий успешный snapshot, переживает временные сетевые ошибки и не дает кэшу бесконечно расти. Политика намеренно простая для защиты курсовой: один TTL, одна Room-таблица, одна директория файлового кэша и одно явное действие очистки в настройках.
