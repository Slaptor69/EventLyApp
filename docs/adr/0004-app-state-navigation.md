# ADR 0004: Навигация через AppState

## Статус

Принято.

## Контекст

В приложении небольшое количество верхнеуровневых экранов и вкладок. Навигация должна легко объясняться на защите и соответствовать существующей Elm-style архитектуре.

Использование полноценного navigation graph добавило бы еще одного владельца состояния. В проекте уже есть `AppState`, `AppMsg`, `AppReducer` и `AppViewModel` для состояния уровня приложения.

## Решение

Представить навигацию как часть Elm-среза приложения:

- `AppScreen` определяет полноэкранные destinations.
- `MainTab` определяет destinations вкладок внутри `MAIN_TABS`.
- `AppState` хранит текущий экран, выбранную вкладку и редактируемую задачу/запись.
- `AppMsg` хранит события навигации.
- `AppReducer` изменяет состояние навигации.
- `EventlyAppRoot` отрисовывает Compose-экран через `when (appState.currentScreen)`.

Бизнес-действия не принадлежат этому навигационному срезу. Например, `AppMsg.AddTaskClicked` открывает экран создания задачи, а `PlannerMsg.AddTaskRequested` создает задачу.

## Итоги

Навигация явная, тестируемая и простая для чтения. Компромисс в том, что deep links и сложное поведение back stack не моделируются через Android Navigation Compose. Для текущего размера проекта более простая state-based навигация достаточна.
